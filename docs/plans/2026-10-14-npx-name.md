# Plan: stop advertising `npx -y kanchanflow-mcp` until the package is published

- **Severity:** P1 (broken install path and a package-name squatting risk; MCP Center C13.npm)
- **Effort:** S
- **Status:** plan only. Implementation follows after approval.

## Finding

1. **The package does not exist on npm.** Measured 2026-10-14: `curl -s -o /dev/null -w "%{http_code}" https://registry.npmjs.org/kanchanflow-mcp` returns **404**.
2. **The homepage tells every visitor to run it anyway.** src/homepage.ts:468-469 renders the stdio client config `{ "command": "npx", "args": ["-y", "kanchanflow-mcp"] }`, shown at src/homepage.ts:575.
   - Today that config fails for anyone who copies it.
   - Worse: the name is unclaimed. Anyone can publish `kanchanflow-mcp`, and every desktop that copied the snippet would then download and run that stranger's code with `-y` (no prompt).
3. package.json already has `publishConfig.access: public` and `bin`, so the repo is ready to publish, but nobody has done it.

**Audit run** (2026-10-14 13:18 UTC, commit `3706839`, local HTTP build on :3937, path `/mcp`, `audit-live-mcp.mjs` with the forbidden-brand list and `--sample-tool kanchanflow_get_pricing`): 3 fail · 6 warn · 26 pass.

**Not checked:** whether the founder intends to publish to npm at all (the deployment plan leaves it as a separate step).

## Proposed fix

Pick one (founder decision below):

- **A. Claim the name now (recommended).** Publish `kanchanflow-mcp` from a KanchanFlow/Soor-owned npm account after the brand-isolation plan merges (that plan removes internal docs from the `files` set). Keep the homepage snippet.
- **B. Do not publish yet.** Change src/homepage.ts to show the local-path config the README already documents (`node /absolute/path/to/dist/index.js`) and drop the `npx` snippet until a version exists. Optionally claim the name with a placeholder version so it cannot be squatted.

Either way, add a release checklist line to the README: "the homepage snippet must name a published package".

## Tests to add

- Homepage test: under option B, the HTML contains no `npx` command; under option A, a test pins the package name in the snippet to `package.json` `name`.
- Release step (manual): `npm view kanchanflow-mcp version` equals `package.json` version.

## Risks and founder decisions

- **Founder decision: npm publish and owning account.** The publisher account is public metadata, so it must be a KanchanFlow/Soor identity, never a sibling-company one (brand isolation).
- **Order.** Publishing before the brand-isolation plan merges would ship the internal SEO docs to npm permanently. Merge that first.
