# Plan: CI workflow and type-checking the tests

- **Severity:** P2
- **Effort:** S
- **Status:** plan only. Implementation follows after approval.

## Finding

1. **No CI.** The repo has no `.github/` directory and no workflow. Typecheck, build and the test suite (9 files, 162 tests passing on main, measured) only run when someone remembers to run them locally.
2. **Tests are never type-checked.** `tsconfig.json:24` excludes `src/**/__tests__/**`, so `npm run typecheck` never checks the tests. Vitest strips types without checking them, so a type error in a test passes silently.

## Proposed fix

1. **`.github/workflows/ci.yml`:**
   - Triggers: `on: push` (branches: main) and `pull_request`.
   - One job on `ubuntu-latest`, `permissions: contents: read`.
   - `actions/checkout@v4`, then `actions/setup-node@v4` with `node-version: 22` and `cache: npm`.
   - Steps: `npm ci`, `npm run typecheck`, `npm run build`, `npm test`, `npm audit --omit=dev --audit-level=high`.
   - The audit step fails on main today (measured 2026-10-14: 5 advisories, 1 critical, 1 high, all via the MCP SDK). Land the dependency-advisories plan first, or add the step as `continue-on-error: true` until it does.
   - Once the deployment plan adds `scripts/check-versions.mjs`, add it as a step (skill D4: version parity in CI).
   - Pin the actions to major versions (or SHAs, if the founder prefers).
2. **`tsconfig.test.json`:** extends `./tsconfig.json`, includes `src/**/*.ts`, sets `noEmit: true`, and has no exclude for tests. Also add `"types": ["node"]` and vitest globals if they are used. They are not: the tests import from `vitest`.
3. **package.json scripts:**
   - `"typecheck": "tsc --noEmit -p tsconfig.test.json"`, which covers src and the tests.
   - The build keeps `tsconfig.json`, so tests never reach `dist/`.
4. **Fix existing type errors.** If enabling this surfaces type errors in existing tests, fix them in the same PR without changing what the tests assert. Not yet measured.

## Tests to add

- The workflow is its own test: open the PR and see it go green.
- A deliberate type error in a test file must fail `npm run typecheck` locally. This is a check during implementation, not something to commit.

## Risks

- **Audit noise.** `npm audit` depends on the advisory database, so a new advisory can turn a green build red with no code change. `--audit-level=high` limits that to serious ones.

- **Tests may need type fixes** after the switch. Effort stays S unless there are many.
- **Future workflows.** The freshness plan adds a second workflow (scheduled sync). It can reuse the same setup steps.
