## 3. Target contract: a public read-only knowledge layer

**Principles.** Read-only; no workspace, RFQ, quote or customer record behind it. One source of truth: the website's `content/*.js` modules plus the claim register, copied by `npm run sync` at a recorded commit. Only `verified_public` records are served. Counts are computed from the registries, never typed.

**Tools: keep the 24 existing tools; add `search`, `fetch` and 6 verb-entity tools.** Each description states what / when / returns / not-for.

| Tool | What | When to use | Returns | Not for |
|---|---|---|---|---|
| `search` | Ranked search over every served record (features, plans, integrations, pages, glossary, claims) | First call for an open question | top N `{id, type, title, summary, canonical_url, market, status}` | Customer data; unpublished pages |
| `fetch` | One record by `id` returned from `search` | Citing a record | the full record | Arbitrary URLs |
| `kanchanflow_get_market` | One market: availability, `purchasable` (true / false / unverified), charge currency, support language, hreflang group | "Can I buy it in X, billed in what" | `market` | Tax or legal advice |
| `kanchanflow_list_free_tools` | The ungated free tools, with `free_plan: false` stated separately | "Is there a free version" | `free_tool[]` + `trial` | Implying a free plan |
| `kanchanflow_get_claim_status` | One claim by id with state (claimed / explicitly_excluded / not_verified) and the exact allowed wording | SOC 2, residency, certifications, customer references | `claim` | Widening a claim beyond its wording |
| `kanchanflow_list_market_pages` | Per-market page records by family and status | "Which page covers X in market Y" | `market_page[]` | Pages not yet live (served as `planned`, never linked as live) |
| `kanchanflow_get_market_page` | One market page with alternates and sources | Citing a market page | `market_page` | Same |
| `kanchanflow_get_official_figure` | A regulated figure (tax, threshold, e-invoicing rule, standard) | Only for figure-bearing questions | `official_figure` | Any figure without an official dated source and a passed Astra check |

**Common record envelope (added to every collection in the mirror):**

```ts
{
  id: string;
  type: string;
  title: string;
  summary: string;
  canonical_url: Record<Locale, string>;
  market: "US" | "IN" | "GB" | "AU" | "CA" | "DE" | "FR" | "JP" | "IT" | "global";
  locale: string;
  hreflang_group: string | null;
  translation_of: string | null;
  language_review: "none" | "astra-model-review" | "human";
  status: "available" | "beta" | "integration" | "coming_soon" | "unavailable";
  site_status?: "LIVE" | "BETA" | "BUILDING" | "PLANNED";   // the site's own badge, kept verbatim
  last_verified: string;
  refresh_after: string;
  publication_status: "planned" | "draft" | "verified_public" | "held";
  sources: { url: string; captured_on: string; refresh_after: string }[];
  source_commit: string;
  gate: string[];
}
```

Status mapping from the site badge: LIVE → `available`, BETA → `beta`, BUILDING → `coming_soon`, PLANNED → `coming_soon`, connector-only → `integration`, explicitly excluded → `unavailable`.

**Output schemas.** Every tool, old and new, declares an `outputSchema` and returns `structuredContent` that validates against it. A parse failure or a record that fails validation returns an error, never a cached guess.

**Staleness gate.** `sync` writes `meta.syncedAt` and `meta.sourceCommit`. A test fails when the mirror's `sourceCommit` is older than the site commit named in the release checklist, and every response keeps `source.syncedAt`.

## 7. Security and MCP Registry readiness

- **No write or customer-action tools.** No sign-up, demo booking, quote creation or workspace access. `KANCHANFLOW_MCP_AUTH_TOKEN` stays only for a private HTTP instance.
- Every tool keeps `readOnlyHint: true`, `destructiveHint: false`, `idempotentHint: true`; the record set is closed (`openWorldHint: false`).
- Reference reads stay confined to `reference/`; synced site documents that name other brands are not served (#19).
- HTTP hardening from #20 (rate-limit key, Host/Origin guard, CORS, error status) is a prerequisite for any public host.
- **MCP Registry listing only after a security review** of the hosted endpoint and the resynced mirror. #26 prepares the `mcpName` marker; submission waits for that review.
